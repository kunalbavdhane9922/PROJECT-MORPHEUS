# SOS Evidence Portal

A secure web application for accessing emergency audio recordings generated by the Android SOS app. Designed as a privacy-focused, premium evidence dashboard, this platform enables authorized users to log in securely with their mobile app credentials and stream their SOS activity audio.

## Stack
- **Frontend**: React (Vite), React Router, Vanilla CSS
- **Backend**: Node.js, Express, jsonwebtoken (JWT)
- **Database/Auth**: MongoDB (Mongoose), Twilio (SMS OTP)
- **Storage**: Supabase Storage

## Architecture & Security
- **Two-Factor Auth (2FA)**: The backend uses an OTP-based login system for high security. Users must provide their own phone number and one of their **Trusted Contacts'** phone numbers to trigger an OTP sent to both devices via Twilio.
- **Stateless Tokens**: Upon successful OTP entry, the backend issues a JSON Web Token (JWT) strictly for web platform authorization, keeping tokens scoped and timed.
- **Signed Storage URLs**: Audio streams are loaded directly via highly constrained Signed URLs securely generated by the backend on demand, limiting playback windows to 60 seconds to prevent unauthorized sharing. The backend uses the authenticated user's phone number to query `sos_sessions` from Supabase.
- **No Direct Downloads**: UI components actively restrict downloading and cache bypass actions.

## Setup Instructions

### 1. Prerequisites
- Node.js installed (v16 or higher)
- A **MongoDB** database (local or cloud like MongoDB Atlas)
- A **Twilio** account for SMS delivery (if not provided, SMS will just log to the backend terminal)
- A **Supabase** project configured with tables `sos_sessions` and `audio_recordings`, and a storage bucket named `sos_audio`.

### 2. Backend Setup
1. Navigate to the backend directory:
   ```bash
   cd backend
   ```
2. Install dependencies:
   ```bash
   npm install
   ```
3. Copy the `.env.example` file to create your own `.env` file:
   ```bash
   cp .env.example .env
   ```
4. Update the `.env` file with your **MONGO_URI**, **Supabase URL**, **Anon Key**, **JWT Secret**, and optionally **Twilio** credentials.
5. (Optional but Recommended) Run the database seed script to clear the test database and spawn dummy user data for testing:
   ```bash
   node scripts/seed.js
   ```
6. Start the backend server:
   ```bash
   npm run dev
   # (or `npm start`)
   ```
   *The server runs on http://localhost:3000 by default.*

### 3. Frontend Setup
1. Open a new terminal and navigate to the frontend directory:
   ```bash
   cd frontend
   ```
2. Install dependencies:
   ```bash
   npm install
   ```
3. Copy the `.env.example` file (if applicable) or create an `.env` file for Vite if your API port differs:
   ```bash
   VITE_API_URL=http://localhost:3000/api
   ```
4. Start the frontend developer server:
   ```bash
   npm run dev
   ```
   *The app runs on http://localhost:5173 by default.*

## Verification
You can manually verify functionality by doing the following:
1. Make sure both servers are running separately (`npm start` in backend, `npm run dev` in frontend).
2. Go to `http://localhost:5173/login`. 
3. Request an OTP by inputting your Phone Number and one of your Trusted Contacts (if you ran the seed script, you can use User `+1234567890` and Trusted Contact `+1122334455`).
4. Read your terminal log running the backend or your SMS text to find the 6-digit OTP, and input it into the web portal to log in.
5. An auth token is stored in local storage, and the app redirects you to `/dashboard`.
6. Selecting an SOS Session pulls relevant audio recordings matching your phone number and safely renders a 60s signed URL in the internal player.
